# 独立审查与制作策略（v004 之后）

日期：2026-11-11　审查对象：`ep01-codex-entry_v004.mp4`、`ep02-reuse-test_v004.mp4`、`master/` 源码
本轮只做判断和策略，没有改工程，没有调用任何付费生成或账号操作。

## 0. 证据边界

- **看了什么**：v004 全片抽帧（前 3 秒 10fps、12 个原尺寸关键帧）、逐帧运动量与亮度、每 0.5 秒音量、全部组件源码和音频合成代码。
- **不能做什么**：我听不了声音。下面关于 BGM 和配音质感的判断来自合成代码和语速测算，需要你用耳朵确认。
- **没有的东西**：包里没有任何抖音对标视频，我也看不到抖音上现在的头部账号。所以我对"网感"的判断来自通用经验，不是对标实测。这是本项目目前最大的信息缺口，第 7 节会请你补。

## 1. 结论

**你的判断是对的：v004 是一份干净、合格的"深色科技风讲解模板"，不是一个有辨识度的作品。**

它修掉了旧片的硬伤（硬切、死寂、PPT 页），但换来的是另一种平庸：四平八稳、没有记忆点、没有看头。

问题的排序和上一轮的自评相反。上一轮把力气花在皮肤和校验器上，而限制品质的前三名是：

1. **片子里没有值得看的东西**（素材和脚本问题，皮肤救不了）。
2. **真实录屏在画面里是配角**，占比小、文字糊。
3. **前三秒是一张几乎静止的海报**，没有人、没有结果、没有冲突。

工程方面，时间引擎和校验流程值得保留，视觉层建议整体重做。更关键的是：现在的校验只保证"不出错"，不保证"好看"，Codex 可以 15 项全过，交出一条比 v004 更平的片子。

## 2. 真正限制品质的因素（按影响排序）

### ① 内容没有回报：15 秒里什么都没发生

- 全片的信息量是"一个网址 + 一个链接 + 一句工具不等于模型"。没有点击，没有安装，没有结果画面。
- 开场口播是"装 Codex，先认准官方入口"。这是一句指令，没有损失感，没有好奇心缺口，也没有承诺。
- 后 5.9 秒讲"接入 DeepSeek"，但全片没有任何接入的画面，等于预告了一件没演示的事。
- **这是素材决定的上限**：7.5 秒、没有点击、Recordly 美化过的录屏，换任何视觉体系都做不出顶级片子。顶级教程片的第一原则是"先有一个值得看的结果，再设计怎么展示它"。

### ② 录屏名义上是主角，实际是配角

| 实测 | 数值 |
|---|---|
| 录屏清晰可读的时长 | 约 3.9 秒，占全片 26% |
| 全貌镜头时录屏占画面面积 | 26%（1000×536），和旧片的 29% 基本一样 |
| 特写镜头时占画面面积 | 37% |
| 讲解段停靠时 | 10%，且压暗到看不清，只是装饰 |
| 特写里目标链接的文字行高 | 画布上 24px，换到 360 宽手机约 8px（含下划线） |

- 上一轮文档自己定的手机可读线是 12px，主角文字没达到。
- 文字放大后是糊的（见 `work/review2/focus_crop_1to1.png`），原因是源录屏密度太低，再推近只会更糊。
- 聚光压暗把白色网页压成一片灰，画面发闷。引线直接从页面标题文字上穿过去。
- 构图逻辑是"横屏窗口摆进竖屏画布"，上下大面积留黑。任何时刻画面都有 35%–40% 是空的深色。

### ③ 前三秒是一张会打字的海报

- **0–1.5 秒几乎不动**：逐帧运动量 0.2–1.1，同片转场时是 7 以上。10fps 抽帧里前 15 格肉眼几乎一样。
- 首帧没有人，没有结果，没有真实画面。中间那块模糊的灰色斜板本意是"暗示后面有真东西"，实际读起来就是一块灰。
- 指令框里打的问题和大标题是同一件事，信息重复，白用 1.3 秒。
- 配音第一个字在 0.42 秒才出来。
- IP 形象 2.3 秒才出现，直径 172px。前三秒里"个人"是缺席的。
- 整体偏暗：约三分之二的时长平均亮度在 27–47（满分 255）。抖音界面本身是黑的，暗画面在信息流里是退后的。

### ④ 视觉语言是"AI 默认审美"，没有可被认领的资产

- 胶囊标签、圆角玻璃卡片、发光描边、黑底琥珀。这是现在所有 AI 产品落地页和模板的共同长相，做得规整，但放进一百条同类视频里认不出来。
- 所谓 IP 识别只靠两样：一个颜色，一个 172px 的头像。猫咪符号只有 40px，没有被当成资产使用。
- 没有标志性动作，没有听得出来的声音标识，没有只属于这个账号的版式。
- 讲解段的"Codex 卡片 + 模型插槽"本质还是一页 PPT，只是皮肤好看了。

### ⑤ 数字人处在最尴尬的位置

- 整屏假人确实不好，但 v004 走到了另一头：把一个对口型的 AI 人脸缩进 172px 的圆里。太小，建立不了任何连接；又仍然是一张 AI 脸，继承了全部的不真实感。
- 外圈的放射状声纹环像一枚廉价徽章。
- 更根本的矛盾：账号的承诺是"研究型、实测、真实"，而"作者"是一张 AI 生成的脸加合成的声音。这对信任是负资产。
- 合规提醒：据我所知，国内自 2025 年 9 月起要求对 AI 生成合成内容（含数字人、合成语音）做标识，抖音有对应的作者声明功能。**请以平台当前规则为准**，但这件事应该在形态设计时就考虑，而不是发布时才发现。

### ⑥ 动效是"三次爆发 + 长平台"，没有节拍

- 运动量集中在 2.0、4.0、6.5 秒三次转场；7.5–12 秒运动量只有 0.1–0.5，接近静止。
- 上一轮报告"完全静止只剩 0.87 秒"，这个数字是靠背景光晕漂移和特写 2.5% 缓推达成的，观众感知不到。**指标达标不等于有看头。**
- 全片缓动只有三种曲线，入场、运镜、退场用的是同一种手感，所以显得机械。
- 没有节拍网格：BGM 是 96 BPM，转场点却在 1.75、3.8、6.6、12.5 秒，没有一个踩在拍上。
- 字幕按整句出现，没有逐词节奏，也没有重音。

### ⑦ 声音大概率是短板（需要你确认）

- BGM 和所有提示音都是代码里用正弦波合成的。这种做法没有版权风险，但听感通常像电子玩具，撑不起"专业"。
- 配音 84 字、10.44 秒，约每秒 4.8 字（含英文）。抖音知识类常见语速在每秒 5.5–6.5 字。
- 两段配音之间有 1.3 秒空档，靠音乐垫着。

### ⑧ 工程：门槛拦的是"出错"，不是"平庸"

- 15 项校验全是合法性检查：溢出、越界、变速、缺文件。没有一项衡量吸引力或可读性。
- 运镜要手填 `cx / cy / upscale` 坐标。v004 特写里那块占了画面左上角的紫色图片，就是手填坐标的结果，校验器不会拦。
- 品牌层不彻底：组件里还有约 46 处写死的像素位置和字号（Explain 18 处、Opener 8 处、Outro 8 处），没有进 `brand.json`。
- **复用没有被真正验证**：EP02 是搭引擎的同一个模型做的。Codex 从没有只拿着工作单独立做过一期。

## 4. 三条有明显差异的创意路线

三条路线共用第 5 节的硬规格（录屏构图、采集规范、字幕、节拍）。差别在于：**IP 由什么承载，前三秒靠什么留人，世界观长什么样。**

### 路线一｜「实测判词」★ 推荐作为主干

**一句话**：每期是一份实测报告，开场就盖章下结论。

- **IP 载体**：不靠人脸，靠三样可以被认领的东西。
  - 一枚**朱红印章**："实测 ✓ 可用""实测 ✗ 别装""实测：官方入口"。盖章的动作和"咚"的一声是全账号的签名。
  - 你的声音。
  - 固定的报告版式。
- **视觉**：暖纸白底、墨黑字、朱红一个强调色，像一份排版考究的测评报告。
  - 白色网页和软件界面放在纸白底上是自然的，不需要压暗，旧片"暖书房撞白网页"和 v004"白页压成灰"的问题一起消失。
  - 亮画面在抖音的黑色界面里是往前跳的。
  - 深色界面（终端、深色模式软件）作为带投影的"实物"放在纸面上，同样成立。
- **前三秒**：
  - 第 0 帧：真实画面铺满上方 70%（结果画面或踩坑画面），下方两行超大判词，印章已经在半空。
  - 约 0.15 秒：印章落下，配一声重音和两帧轻微震屏。配音同时开口。
  - 0.8–2.0 秒：本期各步骤的真实画面快闪 3–5 格，每格 6–8 帧，踩在拍上，带"1/3、2/3、3/3"计数。
  - 2.0–3.0 秒：镜头已经在向第 1 步推进。
- **手机观感**：信息流里一眼是"白底、大黑字、一枚红章"，和周围的深色霓虹科技视频完全不同。
- **复用成本**：低。每期改判词、印章文字、证据片段。印章、版式、快闪都是固定组件。
- **风险**：太"编辑部"，可能显得冷。用口语化的文案和你的声音来补温度。纸白在夜间可能刺眼，所以用暖白而不是纯白。

### 路线二｜「桌面现场」

**一句话**：从你真实的书桌进入屏幕，人以"手"和"声音"在场，不露脸。

- **IP 载体**：真实的环境质感。暖色台灯、键盘、显示器、你的手。已确认人像里的"暖书房"由真实拍摄来实现，而不是由 AI 人像来代表。
- **视觉**：实拍开场 + 标志性的"推进显示器"转场，之后进入清晰的录屏。色调沿用暖色，但来自真实光线。
- **前三秒**：手敲下回车或点下鼠标的实拍特写（真实动作，带真实键盘声），镜头推进显示器，屏幕内容无缝接上录屏，大字判词压在上面。
- **手机观感**：真实感最强，"这是一个真人在真的操作"。
- **复用成本**：中。需要你一次性用手机拍 20–30 条通用空镜（约半小时），之后每期从库里按标签挑选，不用每期拍。
- **风险**：成片质量取决于你拍的素材质量；空镜用久了会重复，需要每季度补拍。

### 路线三｜「角色主持」

**一句话**：一个设计出来的角色（眼镜、黑毛衣、猫）当主持人，表情丰富，画面占比大。

- **IP 载体**：角色本身。明确是"角色"而不是"假人"，没有恐怖谷，表情可以夸张。
- **视觉**：扁平或半立体插画风，颜色更活泼。角色从屏幕窗口下沿探出来，指着操作位置，用 4–6 种表情反应（皱眉、得意、震惊）。
- **前三秒**：角色大表情 + 大字 + 真实画面。
- **手机观感**：亲和，记得住，适合小白。
- **复用成本**：每期为零（代码驱动表情和嘴型），但前期要一套高质量的角色设计。
- **风险**：成败完全取决于角色画得好不好。我用代码能画好一只几何风格的猫，但画不好一个有魅力的人物；高质量人物需要找插画师或用生成工具（付费，需你批准）。画得一般会显得幼稚、廉价。

### 路线对比

| | 路线一 实测判词 | 路线二 桌面现场 | 路线三 角色主持 |
|---|---|---|---|
| IP 靠什么 | 印章 + 声音 + 版式 | 真实环境 + 手 + 声音 | 角色 |
| 前三秒靠什么 | 结论和证据 | 真实动作 | 表情 |
| 与"研究型实测"人设的契合 | 最高 | 高 | 中 |
| 需要你提供 | 合格录屏 | 录屏 + 一次空镜拍摄 | 录屏 + 角色设计决定 |
| 每期成本 | 最低 | 低 | 最低 |
| 最大风险 | 偏冷 | 素材质量 | 角色设计质量 |
| 现有 AI 人像怎么办 | 退出正片，可留在主页头像 | 退出 | 作为角色设计的参考 |

### 我的推荐

**以路线一为主干；路线二的实拍空镜作为可选的开场增强（你愿意拍就加）；路线三暂不做，但把猫做成一个小型品牌符号留作以后的延展。**

理由：
- 路线一把 IP 建在"每期一个盖章结论"这个**形式**上。它不依赖任何一次性素材，不依赖 AI 人脸，Codex 最容易稳定复现。
- 它直接解决第 2 节的 ②③④⑤ 四个问题。
- 它和账号承诺一致：实测、真实、给结论。

**但这个推荐不应该靠文字决定。** 正确的做法是先出静态风格帧，放到手机上和你认可的对标视频并排看，再定。见第 8 节。

## 5. 无论选哪条路线都要执行的硬规格

### 5.1 采集规范（最大的单项杠杆）

现在的清晰度问题，后期解决不了，只能在录制时解决。

| 项目 | 规格 | 目的 |
|---|---|---|
| 分辨率 | 2560×1440 或更高，60fps | 提高像素密度 |
| 系统缩放 + 浏览器缩放 | 合计约 200% | 让界面文字本身就大 |
| 窗口 | 只录一个窗口，逻辑尺寸不超过约 1280×800 | 竖屏里不用缩很小 |
| 工具 | OBS 原始采集，不做自动缩放和美化背景 | 运镜由母版统一做 |
| 操作 | 每一步真实点击，点击前停半秒 | 给镜头留出预判时间 |
| 点击记录 | 同时运行一个小记录脚本，记下每次点击的时间和坐标 | 让引擎自动生成运镜（见 6.2） |
| 干净度 | 关通知、清标签页、用演示账号、不出现真实密钥 | 真实性与隐私 |
| 目标 | 源画面正文大写字母高度不低于约 22px | 放大 1.6 倍以内就能在手机上达到约 11px |

### 5.2 录屏构图：竖屏重构，不是把横屏窗口摆进去

- **竖屏视口**：把录屏当成一张大画布，镜头是一个竖着的取景框（约占画面高度 58%–65%），跟着操作移动。不再把整个横屏窗口缩小摆在中间。
- **位置认知用小地图解决**：角落放一个整窗缩略图，标出当前取景框的位置。全貌镜头只在每步开头出现约 0.6 秒。
- **不压暗页面**：强调用描边、局部放大镜、箭头，不把整页压灰。
- **标注不压内容**：引线和标签走页面空白处，校验器检查它们是否盖住了文字区域。
- **验收线**：录屏段内，真实画面平均占安全区面积不低于 55%；被强调的目标文字在画布上不低于 34px。

### 5.3 字幕

- 逐词出现，重音词放大并变色；字号 64–72px，粗体加描边，放在画面 62%–72% 高度。
- 每屏不超过 2 行、每行不超过 10 个字。
- 语速目标每秒 5.5–6.5 字；配音第一个字在 3 帧以内出来。

### 5.4 节拍与动效

- 全片一个节拍网格（由 BGM 的 BPM 决定），所有转场、印章、快闪、标注出现都吸附到拍点。
- 按角色分三类手感：入场用带回弹的弹簧，运镜用无回弹的阻尼，退场用快速收束。时长用"拍"而不是"秒"来写。
- 规则：任何一个镜头超过 2.5 秒没有新事件（运镜、标注、切换）就算违规。**用"事件密度"代替"像素有没有变"作为指标。**

### 5.5 声音

- BGM 和提示音换成真实采样。需要 3–5 首固定的品牌曲和一套提示音，带 BPM 和拍点信息。来源二选一：你批准购买一次性授权，或我整理一份免费可商用的候选清单由你确认许可。
- 做一个 0.4 秒的声音标识（印章声 + 两个音），每期开头和结尾各出现一次。
- 配音建议做一次盲听对比：你的真人声音 vs 豆包。用手机外放听，不看画面。真人声音对"实测"人设的加分很可能超过省下的那点时间。
- 配音按整句生成，段落之间不留空档；需要"看操作"时让声音继续讲，而不是停下来等。

### 5.6 脚本

- 开场一句话不超过 14 个字，必须包含结论或损失，并且有画面证据。
- 每个上屏的结论必须对应一段真实录屏。没有证据的话不能进片子，包括"下一步接入 DeepSeek"这类预告。
- 示例方向（**都需要先实录取证，不能照抄**）：
  - 结果型："这是装好的 Codex，全程 3 步。"
  - 踩坑型："搜 Codex 下载，排在前面的不一定是官方。"（必须有真实搜索结果录屏才能用）
  - 判词型："官方入口只有这一个。"

## 6. 如何让 Codex 独立做新一期时仍保持质量

核心思路：**把"审美判断"尽可能变成引擎的默认行为和可测的门槛，把留给 Codex 的自由度压到"选模板、填事实、看图自检"。**

### 6.1 从"合法性校验"升级为"质量评分"

每次渲染输出一张评分卡，不达标直接失败：

| 指标 | 门槛（初值，定稿后校准） |
|---|---|
| 首帧 | 含真实画面，占比 ≥ 50%；含判词大字 |
| 配音起始 | ≤ 0.1 秒 |
| 前 1.5 秒事件数 | ≥ 3 |
| 录屏段真实画面占比 | 平均 ≥ 55% |
| 被强调文字高度 | ≥ 34px |
| 最长无事件时间 | ≤ 2.5 秒 |
| 拍点吸附 | 关键事件偏离拍点 ≤ 1 帧 |
| 语速 | 每秒 5.5–6.5 字 |
| 无配音空档 | ≤ 0.6 秒（片尾除外） |
| 结论证据 | 每个印章和判词都挂了证据片段 |

### 6.2 取消手填坐标，改为自动导演

- 运镜由点击记录自动生成：点击前 0.4 秒开始推近，点击时出涟漪，结果出现后停稳。
- 取景框根据目标框自动计算，自动避开空白和无关大图，自动保证文字高度达标。
- 每期配置里只写"这一步的目标是哪个按钮、对应哪句话"，不写 `cx / cy / upscale`。
- 没有点击记录时的退路：用光标追踪和画面变化检测自动找候选点，由 Codex 确认。

### 6.3 场景语法库与配方

- 片头 3 种原型：结果先行、踩坑对比、步骤快闪。每种是固定组件，带字数和素材约束。
- 步骤镜头预设：建立、推近、点击、结果、对比。
- 4 种内容配方：安装类、避坑类、技巧类、对比类。Codex 先选配方，再填内容。

### 6.4 防止视觉漂移

- **设计令牌**：把组件里所有写死的位置、字号、时长清进品牌层，包括动效令牌（弹簧参数、拍数）。
- **基准帧回归**：用一期固定的样例，保存一组"定稿基准帧"。任何对 `src/` 的改动都要和基准帧做像素对比，差异超阈值就失败。
- **样张手册**：一份由定稿帧组成的图册，写明每个组件"对的样子"和"错的样子"。

### 6.5 看图自检写进工作单

- 渲染前先出一张"取景校样"：每个镜头一格，带编号。
- 工作单要求 Codex 逐格回答固定问题：目标在不在取景框中心区域、有没有无关内容占大面积、标签有没有压字。答不过不许出正式版。

### 6.6 真正的交接测试

定稿后，**让 Codex 只拿工作单和一组新素材，独立做一期**，我不参与。评分卡通过、你在手机上看不出和我做的那期有档次差，才算可复用。这一步 v004 没做过。
