# 这套做法能否固定为方法

2026-11-12　对象：本期成片 `阿泽_Codex三步换DeepSeek_v001.mp4` 和它的合成工程 `comp/`

## 结论

骨架可以固定，取景和钩子不行。

- **能固定的**是一套版式、三条内容规则和一条生产流水线，下面第 1 节列出。
- **不能固定的**是所有带坐标和时间的东西：每个镜头的取景、变速、标注位置，以及钩子里为这句文案定做的图形。换一期全部要重做，目前只能靠人看校样图手调。
- **交给 Codex 之前**还差四样：能发现未知位置密钥的检查、不靠手量的取景、钩子的原型库、一次真正的独立交接测试。
- **审查里的路线要改**：数字人不退出正片，改成固定的「主持卡片」；其余硬规格保留，其中采集规范这次没有被满足，仍是画面质量的最大短板。

## 证据边界

- 我听不了声音。口播是否自然、字幕是否踩在字上，我只核对了识别时间戳和静音检测，没有听过。
- 我没有在手机上连续播放过成片。画面判断来自静帧、每秒拼图和逐帧差值。动效的手感（快慢、是否晃眼）需要你看。
- 没有抖音对标原片。抖音界面遮挡区是经验估计，没有真机核对。
- 这一期没有发布，没有任何数据。下面说「可以固定」，意思是结构上能复用、检查项能通过，不是说它能提高完播或转化。

## 1. 可以固定的

### 版式骨架

| 段落 | 固定下来的结构 | 本期对应 |
|---|---|---|
| 钩子 | 上半区是大字口播加一个图形，下半区是中等大小的数字人卡片，约占画面四分之一 | 0–18.3 秒 |
| 步骤 | 上方步骤栏，中间录屏主画面占画面高度 52%，左下数字人画中画，右侧两行字幕 | 18.3–54 秒 |
| 片尾 | 回到钩子的版式，上半区是三步回顾和关注引导 | 54–64.3 秒 |

- **数字人只有两种状态，中间连续变形**。素材全程 1.0 倍速不间断播放，只改位置和裁切，所以没有「满屏人像硬切录屏」，口型也不会错位。
- **录屏卡片在钩子里先以小卡片出现**，放三步的实拍快闪，再放大成主画面。从钩子到教程是同一个元素长大，不是切镜头。
- **底部 316 像素是深色底栏**，只放可有可无的路线信息。这一块在抖音里会被文案和底栏盖住，深色能保证平台白字可读。
- **视觉语言**：暖纸白底、墨色线框加硬投影的卡片、朱红一个强调色。重点词统一是朱红底白字。

### 内容规则

- **上屏的口播文字必须和确认稿逐字一致**，由脚本自动比对，不一致就不出片。
- **标注只标画面里真实存在的控件**。红圈加墨色标签；位置不稳的时候改成钉在卡片顶部或底部。
- **口播说到但没有镜头的地方，三选一**：用相邻的真实结果画面顶上、做成明显是排版的文字卡、或者只留字幕。不许造界面。本期三处缺口都是这样处理的，见制作说明。
- **印章只盖在真实的结果画面上**。本期「实测连通」盖在 CC Switch 自己弹出的连通提示上，不盖在口播的结论上。

### 流水线

1. 逐段审片，写素材清单：每段的用途、时间轴、敏感信息、缺口。
2. 写剪辑表：每个镜头的成片时间、原片时间、取景关键帧。
3. 生成录屏轨，同时出取景校样拼图。看图改表，直到每格都对。
4. 敏感信息在生成录屏轨这一步烧进画面，合成工程只拿到打过码的中间文件。
5. 合成、出静帧、看图、再出整片。
6. 合入口播、标准化响度、跑质检，写进新的版本目录，不覆盖旧版。

这六步本期都跑通了，后四步各有一条命令。

## 2. 取决于本期素材、换题就失效的

- **全部取景坐标**。本期录屏是带自动缩放的成品，画面自己在推拉，我只能在每个时间点手量位置，再反向抵消。26 个镜头、53 个取景关键帧都是这样来的。
- **每个镜头的变速**。录屏和口播不是一起录的，操作快慢对不上，本期最慢的镜头放到 0.42 倍，最快的加到 1.5 倍，还有一处定格 1.85 秒。
- **钩子里的图形**。磁盘条、输入框、对比卡是为「C 盘爆满、只发一句话、网页 AI 只能陪聊」这三句定做的。
- **钩子的长度**。这份文案的钩子有 18.7 秒，而且讲的是清理 C 盘，本期没有这个画面。结果是第一个真实镜头到 14.2 秒才出现。这是文案和素材决定的，版式救不了。
- **打码的位置**。遮罩矩形只对这一条录屏的这一段有效，弹窗一移动就失效，所以我把可用区间卡死在弹窗静止的 1.2 秒内。
- **「三步」**。步骤栏、底栏、回顾都按三步写死。
- **数字人整段连续**。本期数字人是一条 64 秒的完整口播，才能连续播放加变形。如果下期分段生成，或者换真人配音而没有对应的口型视频，这个做法要另想。

## 3. 交给 Codex 复用还缺什么

### 缺的检查

| 检查 | 现状 | 缺口 |
|---|---|---|
| 密钥 | 文本文件扫密钥样式字符串；核对弹窗位置和遮罩假设一致；核对成片里遮罩是实心块 | 只能验证「我知道的那一处」已盖住。录屏别处如果还有密钥，查不出来。这台机器没有文字识别工具 |
| 过程镜头误用 | 生成脚本里按片段编号禁用 D | 应该在素材清单里给每段写「可用 / 禁用」字段，脚本读这个字段，而不是认文件名 |
| 字幕与文案 | 已自动比对 | 时间只来自识别结果，没人听过 |
| 安全区 | 只有一张叠了遮挡区的校样图，靠人看 | 应该自动检查文字框有没有进遮挡区，并用真机截图校准遮挡区 |
| 可读性 | 没有 | 应该量出每个镜头里目标文字在成片上的高度，低于门槛就报错。本期有几个镜头的界面文字在手机上估计只有 5–7 像素 |
| 口播与画面对应 | 人工对照 | 应该有一张表：每句口播对应哪个镜头，或者明确标「无镜头」 |

### 缺的自动化

- **取景**。最该做的一项。录屏时同时记下每次点击的时间和坐标，取景就能自动生成。前提是录屏不带自动缩放，这又回到采集规范。
- **钩子原型库**。把本期的磁盘条、输入框、对比卡、三步快闪抽成几个带参数的原型，Codex 选一个填字，而不是每期现写。
- **基准帧回归**。存一组本期定稿帧，以后改合成代码就做像素对比。

### 缺的规范

- **素材清单模板**：用途、时间轴、敏感信息、缺口、可用或禁用。
- **文案约束**：钩子多长、每句是否有镜头。建议规定第一个真实镜头最晚在第几秒出现，本期是 14.2 秒，偏晚。
- **采集规范**：见第 4 节。

### 缺的验证

Codex 还没有只拿着工作单和一组新素材独立做过一期。这一步不做，「可复用」只是我的判断。

## 4. 审查里建议的路线要不要改

要改三处，其余保留。

**改：数字人不退出正片。** 审查推荐「实测判词」路线，数字人退出。你这一轮明确要用数字人，并且要它不小到看不见。本期的做法是把它定成主持卡片：钩子和片尾占四分之一画面，步骤段是 260×320 的画中画。纸白、墨线、朱红、印章这些来自原路线，继续用。画面左下角一直带着「AI 数字人」小字标识，发布时是否还要在平台勾选声明，请以抖音当前规则为准。

**改：节拍网格换成口播锚点。** 审查要求所有动效吸附到背景音乐的拍点。本期没有批准的音乐，所有出现时间都锚在口播的逐字时间戳上。在有音乐之前，这是唯一可用的时间基准。

**改：评分卡里「首帧含真实画面」这一条。** 本期首帧是大字、磁盘示意条和数字人，没有录屏。原因是钩子讲的事没有画面。这一条要么改成「没有对应真实画面的承诺不许当钩子」去约束文案，要么承认钩子可以是排版。我建议前者。

**保留，而且这次没做到：采集规范。** 本期录屏是 1834×1032、界面 100% 缩放、自带推拉。竖屏取景后多数镜头要放大 1.3–1.8 倍，最多约 2.5 倍，文字发虚，推拉时还带运动模糊。后期已经做到头了，下一期请按规范录：只录一个窗口、界面放大到 200% 左右、不加自动缩放、每次点击前停半秒。

**保留：其余硬规格。** 竖屏取景、字幕不压界面、不压暗页面、没有证据的结论不上屏，本期都照做了。小地图没有做，位置感目前靠步骤栏。

**没做：先出风格帧再定路线。** 这一轮按你的要求直接出了成片。它现在就是那张风格帧，请在手机上看过再决定这套视觉是不是要定下来。

## 需要你决定的

1. 这套版式和视觉要不要定为账号的固定样式。
2. 声音：现在只有口播，没有音乐和提示音。是批准一套可商用的音乐，还是发布时用抖音站内音乐。
3. 下一期能不能按采集规范录屏，并且录的时候让我或 Codex 同时记点击日志。
4. 是否安排一次 Codex 独立交接测试。
