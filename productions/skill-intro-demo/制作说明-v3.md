## 1. 我怎么理解用户说的第一点

**v2 的问题**：v2 一共 6 屏，每屏 5–6 秒。每屏放完就整屏虚化退场，下一屏的卡片再重新进场：

```
[卡A 出现] → [卡A 消失] → [卡B 出现] → [卡B 消失] → [卡C 出现] …
```

这就是用户说的「出现-消失-出现」。每 5 秒观众就要重新找一次视线焦点，节奏是碎的。

**参考片的做法**：我回到参考片，按每秒 1 帧逐段看了 20–52s、108–124s、138–154s 三段，确认它在**一个部分内部从不换卡**：

- 「一眼就能看出是 AI 做的」：顶部胶囊一直留着，两张卡先被打上 ×；接着**同一组卡翻面**，变成「01 真实画面 / 02 组件」，再打上 √。
- 「头部财经博主·拆片」：先出现一张空卡，三行逐行填进去、由虚变实；然后**这张卡左移让位**，右边加进「我的片子」，再逐项打 √/×。
- 「AI → 成片」：先画出一条弯路，标出「点按钮 / 拖时间线」；然后**整条弯路变淡上移**，下面再画出一条紫色直线「写代码」。

只有这一部分讲完，整组才一起退场，换下一部分的新卡：

```
[部分 A 的卡 出现] → 变化 → 变化 → 变化 → [部分 A 整体消失] → [部分 B 的卡 出现] → 变化 → …
```

也就是用户说的「出现-变化-消失-出现」。

**v3 的实现**：

1. **时间轴从「6 屏」改成「3 个部分」**：A 14s、B 12.5s、C 17s，共 43.5s。部分内部大约每 3–5 秒变化一次，节奏仍符合参考片「每 4–6 秒有新东西」，但画面主体一直在。
2. **引擎加了两种「变化」原语**，部分内部只用它们推进，不再让卡片离场：
   - `state`：原位换状态。标题、卡头、某一行文字在同一位置从旧状态过渡到新状态：旧的上飘虚化，新的逐字浮现。v3 的标题在每个部分里都**在原位连换 3–4 次**，从不离场。
   - `move`：卡片移动、缩放、改尺寸、改透明度。用于卡片叠压、退后、合并、左移让位，以及「文件夹 ⇄ 文档」的变形。
   - 再加上原有的 `fill`（占位行填满）、`mark`（荧光笔）、`badge` / `unbadge`（打上 / 撤掉 √×）。
3. **只有部分结束才 `out`**：引擎只在每部分的最后 0.45s 让整组一起虚化退场，部分内部不会出现整卡消失。
4. **自动校验**：每个部分在开场 1.5s 之后，必须至少有 2 次「变化」，否则直接报错，提示会退化成「出现-消失-出现」。当前三个部分分别有 12 / 8 / 5 次计入校验的变化 cue（state / move / fill / mark / badge；部分 C 另有换面用的淡入淡出，不计入）。

### 三个部分具体怎么变

| 部分 | 时间 | 出现 | 变化（同一组卡上） | 消失 |
|---|---|---|---|---|

整个部分 C 从头到尾只有**一张卡**在变形，这是最能体现「出现-变化」的一段。

## 2. 我怎么理解用户说的第二点：口播框和居中构图

**v2 的问题**：v2 为了避开左下角的口播框，把整个主视觉列定在 x 456→1824，中心 x=1140，连字幕也居中在 1140。结果整页看起来往右偏了 180px。

**v3 的做法**：

- **中轴回到画面正中 x=960**。标题、主卡、字幕的中心都落在 960 上，引擎逐帧检查，偏差超过 ±4px 就报错。
- **口播框不动**：仍是竖屏 9:16、280 × 498、左上角 (96, 528)，和 v1/v2 完全一致，后期素材不用重新对位。
- **用「对称安全列」避让**：口播框右缘 376，加 40px 留白得到 416；以 960 为轴镜像到右边是 1504。画面下半部（和口播框同高，y > 488）的大字、卡片、字幕都放在 **x 416 → 1504** 之内，所以既居中，又不会压到口播框；画面上半部的标题区可以用满全宽。
- 字幕条最宽 1088px（约 30 个字），永远以 960 为中心，不会再靠右。
- **逐帧版式审计**：引擎每 0.25 秒采样一次，所有可见的卡片、大字、胶囊、芯片、徽标、字幕都不能进入口播禁区，也不能越出安全区。卡片移动、放大的中间帧也算在内，当前 0 条违规。
- 参考线截图：`demo-v3/stills/t37.00_guides.png`。蓝色竖线是中轴 960，浅蓝区是对称安全列，红斜线区是口播禁区。

> 唯一有意越出对称列的元素：部分 C 中 SKILL.md 文档右边缘的两个黑色标注胶囊，右端到 x≈1520。它们是压在卡边上的批注（参考片也是这么做的），在口播框对面，不影响居中，也不挡任何东西。

## 3. 和 v2 相比改了什么

| 维度 | v2 | v3 |
|---|---|---|
| 转场逻辑 | 6 屏，每屏 5–6s 后整屏退场再换（出现-消失-出现） | 3 个部分，每部分 12.5–17s；部分内部用 `state` / `move` / `fill` / `badge` 在同一组卡上变化，部分结束才整体退场（出现-变化-消失-出现） |
| 标题 | 每屏一个标题，随屏一起进出 | 每个部分一个标题位，在原位连换 3–4 个状态，逐字打出 |
| 卡片 | 每屏新建一张卡 | 叠压 / 退后 / 合并（A）、填满后左移让位（B）、文件夹 ⇄ 文档变形（C） |
| 构图 | 主视觉列 456→1824，中心 1140，字幕偏右 | 中轴 960；下半部用对称安全列 416→1504；字幕永远居中 |
| 口播框 | 280×498 @ (96, 528) | **不变** |
| 校验 | 每屏 4.5–6.5s、元素静态位置 | 每部分 10–18s、每部分至少 2 次变化、逐帧（0.25s）版式审计 + 居中检查 |
| 时长 | 35.0s | 43.5s |
| 视觉规范 | 炭黑 / 暖白 / 金 / 紫，柔和动效 | 沿用 v2，不变 |

**沿用 v2 的部分**：配色（炭黑 `#19181C` / 暖白 `#FAFAFA` / 金 `#E8B54F` / 紫 `#7B5CF0` / 只在出错时用的红 `#E5484D`）、字体（Noto Sans SC 900 + JetBrains Mono，OFL，已内置）、黑底字幕条、章节数字方块、柔和的入场（上浮 + 去模糊）和 1.4s 深浅舞台切换。

## 4. 工程结构（v3）

```
src-v3/
├─ index.html              开发入口；一个 <script> = 一个「部分」
├─ styles/tokens.css       规范：中轴 960、对称安全列 416–1504、颜色、字号、动效
├─ styles/base.css         舞台、深浅背景、居中字幕条、章节角标、口播框、参考线
├─ styles/components.css   v2 组件 + v3 新增 .c-morph（状态容器）/ .c-card.is-morph（变形卡）/ .c-file / .c-chip
├─ styles/scenes.css       各部分坐标
├─ js/engine.js            时间轴；新增 fx:'state' / 'move' / 'unbadge'；部分规则与逐帧审计
├─ js/components.js        口播框、参考线、逐字拆分、图标、播放器
└─ js/scenes/pA-repeat.js · pB-sop.js · pC-anatomy.js
```

写一个新部分时，「变化」要这样写：

```js
html: `
  <div class="ttl"><div class="c-morph">
    <div data-state="a" class="c-title c-type">第一句</div>
    <div data-state="b" class="c-title c-type">第二句<em>重点</em></div>
  </div></div>
  <div class="c-card card">…</div>`,
cues: [
  { at: 0.2, sel: '.ttl [data-state=a]', fx: 'type' },              // 出现
  { at: 0.5, sel: '.card', fx: 'tilt' },
  { at: 4.0, sel: '.ttl .c-morph', fx: 'state', to: 'b' },          // 变化：标题原位换句
  { at: 4.0, sel: '.card', fx: 'move', to: { x: 470, w: 640 } },    // 变化：同一张卡移动 / 变形
],
// 不要在部分内部对主卡用 fx:'out'；部分结束时引擎会让整组一起退场
```

常用命令：

```bash
python3 tools/build.py --src src-v3 --out demo-v3/index.html   # 子集化字体并打包
OUT=demo-v3 node tools/render.mjs check                         # 时长 / lint（含逐帧审计）/ 口播框坐标 / 外部引用
OUT=demo-v3 node tools/render.mjs stills 9.2 37 --guides        # 导出静帧
OUT=demo-v3 node tools/render.mjs video 30                      # 逐帧导出 MP4（加 --slot=key 出抠像版）
```

## 6. 已知问题

1. **预览没有声音**，时间轴是按口播稿估的，还没对齐真实语音。部分时长（14 / 12.5 / 17s）需要等拿到口播音频或 SRT 后再按真实时间码调整。
2. 部分 A 的卡片叠压时，后面两张只露出卡头和第一行的上沿，第一行文字会露出一点点边。这是叠压的自然效果，但如果你觉得杂，可以让后面的卡在退后时把内容一起淡掉。
3. 部分 C 文件夹 → 文档的变形中，卡片底色从深到白是交叉溶解完成的，中间约 0.3s 会经过一个灰色过渡。参考片的翻面是 3D 翻转，我选了溶解，因为在这个尺寸下更安静；如果你想要更明确的「翻过来」感觉，可以加一个 rotateY 翻面版本。
4. 两个标注胶囊略越出对称列（见第 2 节说明）。如果你希望严格对称，可以把它们改放到文档内部的行尾。
5. 标题字体仍是 Noto Sans SC 900，比参考片的紧缩粗标题体更宽一些（v2 已说明原因）。
