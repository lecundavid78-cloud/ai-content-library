## 2. 对齐语音

- 运行：`tools/align.py asr/口播全片-whisper-base.json refs/用户口播文案.md --from 268.00 --to 359.95 --offset 268.00 --out src-ch04/js/timeline.js --marks …`
- 结果：**39 行字幕**（正文用文案、时间用语音），外加 38 个关键词时间。
- 本章给 `tools/align.py` 补了三条断行规则（前三章的 timeline.js 不重新生成，不受影响）：
  1. 超长分句先在「——」处切：「而是先看一份清单 ／ 也就是每个 Skill 的名称（name）和简短描述（description）」；
  2. 「；」算句末：「再去读 references ／ 需要模板，去 assets 里拿」不再把「需要模板」切到上一行；
  3. 字幕里的「->」显示为「→」：「匹配目录 → 读说明书 → 按需调资源 → 工具执行」。
- 每个卡片变化都对准关键词，注释写在每条 cue 后面。例如三个技能行按「检查 PPT 32.34 / 处理表格 33.64 / 做封面 34.18」逐行出现，三个资源卡按「读 references 62.48 / assets 里拿 64.74 / 需要跑代码 65.94」依次立起，串联胶囊按「匹配目录 77.26 / 读说明书 78.46 / 按需调资源 79.58 / 工具执行 80.70」依次出现。

## 4. 三个部分（出现 - 变化 - 消失 - 出现）

文案是一个小节，口播里有三段明显的内容：「先让平台识别」「五步调用」「自动触发不百分百」，所以分三个部分。

| 部分 | 章内时间 | 出现 | 变化（同一组卡） | 消失 |
|---|---|---|---|---|

| **B · 五步调用** | 16.40–82.60 | 居中大字「整个调用：五步走」 | **顶部五步进度条贯穿整个部分**，讲到哪一步点亮哪一步，下方舞台随之变化：<br>① 看目录：三张「SKILL.md · 全文」卡打 ×（不会全文读一遍）→ 换成一张「Skills 清单」卡，表头 name / description 随口播亮起，三个技能逐行出现，右侧标「正文 · 未读」<br>② 匹配：指令气泡「帮我按统一风格做张封面」→ description 列被荧光笔扫过 → 另两行退后，cover-workflow 高亮打 √ →「也支持手动指定」：气泡原地改成 `/cover-workflow`<br>③ 读说明书：**同一张清单卡原地加高、翻成 SKILL.md 正文**，五个步骤逐行填满<br>④ 调资源：正文卡让到左边，右侧依次调出 references / assets / scripts（标「环境允许时」）<br>⑤ 交付：前面的卡退后，交付卡立起 →「检查并输出」打 √<br>→ 串起来：舞台卡退场，四个动作胶囊随口播依次出现（进度条保留） | 82.15s 整组退场 |

## 5. 沿用方式与本章改动

- `src-ch04/` 的引擎、组件、tokens、base、components 样式都从 `src-ch03/` 复制，与第二、三章相同。只有一处本章专属的小改：**字幕淡出从 200ms 改成 80ms**（`subOut`）。
  - 原因：相邻两行字幕首尾相接，200ms 的淡出会和下一行的淡入重叠，两个黑底条短暂叠在一起；改成 80ms 后几乎看不出；
  - 前几章已交付，没有回改。
- 本章写的：
  - `styles/scenes.css`：版式，新增五步进度条 `.stp`、清单行 `.cr`、资源卡 `.res`、串联胶囊 `.chain`；
  - `js/parts/pA-find.js`、`pB-steps.js`、`pC-caveat.js`；
  - `index.html`。
- 审查时修过的问题：
  - 文件夹芯片里的「cover-workflow/」折成了两行（加宽并禁止换行）；
  - 第三步翻面后出现约 3.5s 的深色空卡（正文面提前到 50.95s 出现）；
  - 五步条未点亮的占位线框太淡（加深）；
  - 清单行的紫色高亮被卡面盖住（给行加 `isolation: isolate`）。
- 渲染：`PAR=3 SHOT=jpeg bash tools/compose_chapter.sh 04`，2782 帧、5 段，一条前台命令完成渲染和合成。
  - 这次墙钟用了 21 分钟，而第三章同样的命令只用 3 分钟。外层 `timeout 580` 没有触发，说明这期间容器被挂起或节流（与第一、二章观察到的现象一致），不是渲染本身变慢。

复现：

```bash
python3 tools/align.py asr/口播全片-whisper-base.json refs/用户口播文案.md --from 268.00 --to 359.95 --offset 268.00 --out src-ch04/js/timeline.js --marks "…"
ffmpeg -ss 268.00 -t 91.95 -i refs/用户口播视频.mp4 -vf "crop=540:960:282:14,setsar=1,tpad=stop_mode=clone:stop_duration=0.7" \
       -af "afade=t=out:st=91.89:d=0.06,apad=pad_dur=0.7" -t 92.65 … demo-ch04/media/presenter.mp4
python3 tools/build.py --src src-ch04 --out demo-ch04/index.html
OUT=demo-ch04 node tools/render.mjs check
PAR=3 SHOT=jpeg bash tools/compose_chapter.sh 04
```

## 7. 已知问题

1. 部分 B 长 66 秒。有顶部进度条和 27 次变化撑着，节奏不拖，但信息量是全片最大的一段；如果觉得密，可以在「串起来」之前把它拆成两个部分。
2. 「也就是每个 Skill 的名称（name）和简短描述（description）」是本章最长的一行字幕（约 29 字宽、约 990px），仍在居中安全列（1088px）内。因为它是一个不可再分的分句，所以没有硬拆。
3. 字幕淡出时长只在本章改成了 80ms，和前三章（200ms）有细微差别。逐章观看察觉不到；如果要统一，可以把前三章也改成 80ms 后重渲（每章约 3 分钟）。
4. 同前几章：没有背景音乐和音效；Whisper base 对个别短词有 ±0.1s 误差，可改 part 文件里对应那一行的 `at`。
