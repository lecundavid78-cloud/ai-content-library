## 1. 全片章节划分

整段口播 585.64s（9 分 46 秒）。我用 Whisper 把全片转写成逐字时间戳，再和文案对齐，得到每个小节标题的开口时间，然后在标题前的静音间隙里下刀。原则是**顺着文案的小节，不把一节拦腰截断**；太短的小节和相邻的、语义最接近的小节合并。

| 章 | 标题 | 起 → 止（口播原片秒数） | 时长 | 对应文案小节 | 状态 |
|---|---|---|---|---|---|
| **01** | **为什么需要 Skill** | **0.00 → 83.50** | **83.5s** | 开场 +「为什么需要 Skill？」 | ✅ 本轮完成 |
| 02 | Skill 长什么样 | 83.50 → 177.15 | 93.7s | 「Skill 在电脑里到底长什么样？」+「SKILL.md 里面到底写了什么？」 | 未开始 |
| 03 | 其他文件有什么用 | 177.15 → 268.00 | 90.9s | 「除了 SKILL.md，其他文件有什么用？」 | 未开始 |
| 04 | AI 怎么发现和调用 Skill | 268.00 → 359.95 | 92.0s | 「AI 是怎么发现和调用 Skill 的？」 | 未开始 |
| 05 | 为什么按需加载 | 359.95 → 415.76 | 55.8s | 「为什么 Skill 要采用按需加载？」 | 未开始 |
| 06 | Skill 和 Prompt 的区别 | 415.76 → 500.50 | 84.7s | 「Skill 和普通 Prompt 到底有什么区别？」 | 未开始 |
| 07 | 值不值得做 + 总结 | 500.50 → 585.64 | 85.1s | 「什么样的任务值得做成 Skill？」+「总结」 | 未开始 |

各小节标题的实测开口时间：83.68 / 106.86 / 177.34 / 268.38 / 360.22 / 415.74 / 500.78 / 542.94s。
上表的切点都落在标题前的静音里（如 176.98–177.37s、267.85–268.14s）。第 2 章及以后的切点，做到那一章时还会用同样的方法复核一次。

**第一章的切点**：「又快又稳」的「稳」在 83.24s 开口，83.42–83.62s 是一段约 0.2s 的静音，下一节「Skill 在电脑里…」从 83.66s 开口。所以从 **83.50s** 切开，声音在 83.44–83.50s 做 60ms 淡出，避免爆音。
成片在 83.50s 之后补了 0.7s 片尾：口播画面停在 83.50s 这一帧（不让他「张嘴无声」），卡片整体退场。所以成片总长 84.2s。以后各章首尾相接时，这 0.7s 就是章与章之间的自然停顿。

## 2. 怎么对齐语音

1. **转写**：用本机 Whisper（base 模型，CPU）对整段音频做中文转写，开启逐字时间戳。全片约 3 分钟出结果。
2. **对齐**（`tools/align.py`）：
   - 字幕**正文用文案**，**时间用语音**。Whisper 会听错字，比如「任务」听成「人物」、「生图」听成「声图」、「稳」听成「闻」，所以正文不能直接用识别结果。
   - 把文案和识别结果都规整成只剩汉字 / 字母 / 数字的字符序列，用 difflib 求最长公共子序列：对上的字直接拿到时间，没对上的字在前后两个已知字之间插值。
   - 文案按分句切成字幕行：句末和冒号必断，很短的分句和后一句合并，超长分句在「、」处切开；英文按半个字宽计算宽度，单行不超过 27 个字宽。句末的「，。」会去掉。
   - 每行比开口提前 0.08s 出现，停到下一行出现前（最多多停 0.25s）。
   - 输出 `src-ch01/js/timeline.js`：一共 **44 行字幕**，再加 50 个关键词的开口时间（marks），供场景卡片对点。
3. **卡片对点**：三个部分里每一次「变化」都写成章节内绝对秒数，并在注释里标出它对的那个词。例如「封面 12.08 / 字体 12.71 / 配色 13.40 / 排版 14.06 / 检查标准 14.64」：交代卡的五行就是随着这五个词逐个填进去的。
4. **播放同步**：网页里以口播 `<video>` 的 `currentTime` 作为主时钟，动画和字幕都跟着声音走，不会越播越偏。导出时逐帧渲染，再和同一份音视频合成，帧级对齐。

## 3. 口播画面怎么裁进窗口

- **窗口不动**：仍是 v3 预留的 **280 × 498（9:16），左上角 (96, 528)**，圆角 20px，带投影。标题、卡片、字幕都以 x=960 居中，下半部只用对称安全列 416→1504，所以窗口既不挡大字和字幕，也不把整页推偏。逐帧审计 0 违规。
- **裁切**：原片 1080×1350（4:5）。我在第一章 0.5 / 12 / 33 / 47 / 60 / 76s 多处试裁，最后取 **540×960 区域，左上角 (282, 14)**，再缩到 280×498：
  - 头顶留白约 45px，眼睛在窗口约 40% 高度，脸完整、视线清楚；他整章左右晃动约 ±40px，都还在框内；
  - 麦克风只露出顶部，大约占窗口底部 22%，不会把窗口挤满；左下角的笔记本和桌面被裁掉了。
- **名牌**：「阿泽」白色小胶囊只在开场出现，7.60s 起淡出，之后窗口里只有人。
- **文件**：`demo-ch01/media/presenter.mp4` 是裁好的 540×960 片段（25fps，含第一章声音，25MB），网页和成片用的都是它。
- **合成**（`tools/compose_ch01.sh`）：HTML 先在导出模式下逐帧渲染视觉层，口播窗口只画外框和投影；然后 ffmpeg 把 presenter.mp4 缩到 280×498，用**从同一份 HTML 截出来的圆角遮罩**（`media/slot-mask.png`）叠到 (96, 528)，再叠上名牌层（`media/slot-name.png`），最后接上口播原声。

## 5. 样式上怎么沿用 v3

- 沿用 v3 的引擎、组件和规范：
  - 配色：炭黑 `#19181C` / 暖白 `#FAFAFA` / 金 `#E8B54F` / 紫 `#7B5CF0`，红 `#E5484D` 只在「漏说配色」时出现一次；
  - 字体：Noto Sans SC 900 + JetBrains Mono，OFL 授权，已内置子集；
  - 字幕：黑底小圆角条；
  - 章节角标：数字方块；
  - 动效：上浮 + 去模糊、逐字打出、纵深卡片、占位填满、荧光笔；舞台深浅切换用 1.4s。
- 构图沿用 v3：中轴 960，下半部用对称安全列，字幕永远居中。
- 引擎在 v3 基础上只加了「对真实时间」所需的部分：
  - 部分用绝对时间段（`span`），cue 用绝对秒数；
  - 字幕从 `Studio.TIMELINE` 读取；
  - 口播视频做主时钟；
  - 导出模式和叠加层截图；
  - `move` 支持从 CSS 里的初始缩放开始（用于大字上移缩成标题）。
- 校验规则针对真实口播做了调整：一章 60–120s，每部分 6–40s；新增「字幕不能重叠、每行至少停 0.5s」。逐帧版式审计（禁区、安全区、居中）保持不变。

## 6. 工程结构

```
src-ch01/
├─ index.html                 开发入口（口播视频引用 ../demo-ch01/media/presenter.mp4）
├─ styles/                    tokens / base / components 沿用 v3（base 增加了视频窗口与导出叠加层）+ scenes（本章版式）
├─ js/timeline.js             ← tools/align.py 生成：44 行字幕 + 关键词时间
├─ js/engine.js · components.js
└─ js/parts/pA-why.js · pB-three.js · pC-sop.js     三个部分，cue 时间 = 口播原片秒数
demo-ch01/
├─ index.html                 构建产物（样式 / 脚本 / 字体已内联）
├─ media/presenter.mp4        裁好的口播片段（540×960，含声音）
├─ media/slot-mask.png · slot-name.png   合成用的窗口遮罩与名牌层
├─ preview.mp4                成片（1920×1080，30fps，有声）
└─ stills/                    关键静帧（从成片截取）
tools/align.py                字幕 / 关键词对齐（文案 × Whisper）
tools/compose_ch01.sh         渲染视觉层 + 叠口播窗口 + 混入原声
```

复现步骤：

```bash
whisper <音频.wav> --model base --language zh --word_timestamps True --output_format json   # 转写（已做过，全片约 3 分钟）
python3 tools/align.py full.json refs/用户口播文案.md --from 0 --to 83.5 --out src-ch01/js/timeline.js --marks "封面,字体,…"
ffmpeg -t 83.5 -i refs/用户口播视频.mp4 -vf "crop=540:960:282:14,setsar=1,tpad=stop_mode=clone:stop_duration=0.7" \
       -af "afade=t=out:st=83.44:d=0.06,apad=pad_dur=0.7" -t 84.2 … demo-ch01/media/presenter.mp4
python3 tools/build.py --src src-ch01 --out demo-ch01/index.html
OUT=demo-ch01 node tools/render.mjs check           # lint + 逐帧审计
bash tools/compose_ch01.sh                          # 成片
```

## 8. 已知问题

1. **Whisper 用的是 base 小模型**。时间戳对于「整句」很准，对个别短词可能有 ±0.1s 的误差。如果你觉得哪张卡片早了或晚了，改对应 part 文件里那一行的 `at` 即可。
2. **字幕正文以文案为准**。口播里如果有和文案不一样的说法，字幕会显示文案的写法。这一章我逐句对照过，没有发现明显出入（例如口播说「交代了封面、字体、配色、排版和检查标准」，与文案一致）。
3. 网页版播放依赖浏览器解码 `presenter.mp4`，拖动进度条后视频会有一瞬间的缓冲。成片 `preview.mp4` 没有这个问题。
4. 片尾 0.7s 口播画面是静帧。单独看第一章时几乎察觉不到；七章连起来时，它会变成章与章之间的停顿。
5. 名牌淡出：网页里是「虚化 + 淡出」，成片里是纯淡出（ffmpeg 叠加层不做模糊），差别不到半秒。
6. 口播窗口在深色舞台（部分 A）上会显得比较亮，因为原片背景是浅灰。这是真人画面本身的颜色，没有做调色；如果需要，可以在合成时给窗口加一点暗角。
7. 第一章没有背景音乐，也没有音效，只有口播原声。
