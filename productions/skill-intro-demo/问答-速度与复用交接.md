### 1.2 是「本来就这么久」还是「有可避免的停顿」？

- **本来就要花的**：每章约 1–1.5 小时。按口播逐句设计卡片变化、写源码、看静帧、修图、写说明。这部分是做「对齐真实语音、每 3–5 秒一次变化」的定制视觉必须付出的，第二章基本就是这个量。
- **可以避免的**：第一章 10 小时里大约 6 小时是损耗。其中「pgrep 自匹配」和「把长渲染丢到会被 10 分钟掐断的后台」两项完全是我的流程问题，合计浪费约 3 小时；会话中断、沙盒重启、CPU 节流是环境问题。

### 1.3 后面几章大概要多久？怎样明显加快？

第 3–7 章口播共约 409 秒，分 5 章，每章 55–92 秒。

- **按现有流水线（第二章的节奏）**：每章约 1.5–2 小时 → **5 章约 8–10 小时**。如果再遇到断线或节流，会更长。
- **可以明显加快的做法**（第三章开始用前两条）：
  1. **并行分段渲染**：同时开 3 个 Chrome，各渲一段；截图改用 JPEG（`SHOT=jpeg`，不再编码 PNG）。在 CPU 没被节流时，渲染能从约 10 分钟降到约 3–4 分钟；更重要的是，暴露在节流和中断下的时间也跟着变短。
  2. **严格前台、短命令**：每条命令不超过 8 分钟；判断任务完成看产物文件，不用 `pgrep -f`。
  3. **先批量出分镜，再批量实现**：先一次写完第 3–7 章的「分部分 + 对点 cue 表」（纯文本，约 30 分钟），审美决策集中做一次；之后每章的实现就是照表把卡片模板填进去。
  4. **卡片模板库**：把已用过的卡片型做成可传参的模板，例如叠压交代卡、三张问号卡、方法包、文件夹卡、文档卡（前置区 / 正文面）、新同事三联。新章节多数镜头可以直接复用，只为新概念（加载流程、对比表）设计新卡。
  5. **交给 Codex 做机械部分**（见第 3 题）：裁切、对齐、build、渲染、合成、截图、校验都可以照命令跑，不需要模型做审美判断。
- **加快后的估计**：每章约 40–60 分钟，5 章约 4–5 小时；如果分镜由我先统一做好、实现交给 Codex 并行推进，还能更快。

## 2. 这套做法能不能复用到第 3–7 章？

**能。** 下面列出已经固定的和每章要重做的。

### 已经固定（直接照用，不需要再设计）

| 环节 | 固定内容 | 位置 |
|---|---|---|
| 转写 | 全片 Whisper base 逐字时间戳，已从 `/tmp` 持久化到项目 | `asr/口播全片-whisper-base.json` |
| 字幕对齐 | 正文用文案、时间用语音；断行规则；`--offset` 输出章内时间；`--marks` 输出关键词时间 | `tools/align.py` |
| 切点 | 7 章切点表（都在静音里），每章开工前用 RMS 复核一次 | 见交接文档第 2 节 |
| 口播裁切 | 540×960 @ (282,14) → 280×498，窗口 (96,528)，圆角 20 | 一条 ffmpeg 命令 |
| 章衔接 | 开头不加停顿；结尾 60ms 淡出 + 0.7s 停帧（`tpad`） | 同一条 ffmpeg 命令 |
| 引擎 | 确定性时间轴、媒体主时钟、state / move / fill / fillLight / mark / badge / restore 等动效、导出叠加层、逐帧版式审计 | `src-ch02/js/engine.js`（每章复制一份） |
| 组件与规范 | 配色、字体、字幕条、章节角标、口播窗口、卡片、胶囊、徽标 | `src-ch02/js/components.js`、`src-ch02/styles/{tokens,base,components}.css` |
| 构建 | 字体子集化 + 内联 | `tools/build.py --src src-chNN --out demo-chNN/index.html` |
| 校验 | lint + 逐帧审计（禁区、安全区、居中、字幕重叠和时长、部分内变化次数） | `node tools/render.mjs check` |
| 渲染 + 合成 | 分段渲染 → 无损拼接 → 圆角遮罩叠口播 → 混原声 | `tools/compose_chapter.sh NN` |
| 舒适度检查 | 逐帧亮度：黑场 / 闪帧 / 亮度突变 | ffmpeg signalstats 命令（见交接文档） |

### 每章必须重新设计、手写

| 环节 | 为什么不能自动 |
|---|---|
| **部分划分与卡片编排**（`src-chNN/js/parts/*.js`） | 每章讲的概念不同：第三章是 scripts / references / assets 三件套 + 权限提醒，第四章是五步调用流程，第五章是按需加载（查字典），第六章是 Skill 和 Prompt 对比两种情况，第七章是值得做的标准 + 三个自检问题。每个部分要决定「哪张卡出现、对着哪个词怎么变」，这是审美和信息设计工作 |
| 版式坐标（`src-chNN/styles/scenes.css`） | 跟着卡片编排走 |
| 标题文案（每次 state 的主句 ≤14 字） | 要从口播里提炼，不能照抄字幕 |
| 审查与修改 | 必须看静帧：有没有拥挤、空白太久、标注错位、和字幕重复 |
| 说明文档 | 每章的范围、部分表、校验结果 |

### 一个实际比例

第二章花了约 2 小时：其中**约 40 分钟是「必须重新设计」的部分**（编排 + 审查），其余是固定流程加上环境节流。

## 3. 能不能把方法交给用户，让 Codex 来做后续章节？

**能。** 交接文档写在 `制作交接-后续章节给Codex.md`，不依赖本会话的记忆：目录约定、切点表、每一条命令、硬约束、验收清单、易错点都写进去了。

### 分工建议

| 工作 | 谁做更合适 | 理由 |
|---|---|---|
| 切点复核、裁 presenter、align 字幕、build、check、分段渲染、合成、截图、亮度检查、写校验表 | **Codex 可以完全做** | 都是确定的命令，有明确的通过标准 |
| 每章「部分 + 卡片编排 + 对点 cue 表」（分镜） | **建议由我（Claude）做**；Codex 也能做，但审美风险较高 | 需要判断信息怎么可视化、哪里留白、哪里不能和字幕重复、什么时候该换卡。前两章出过的返工（字段撞名、代码缩进、开场文字和字幕重复）都发生在这一步 |
| 按分镜实现 parts/*.js 和 scenes.css | **Codex 可以做** | 只要分镜写到「元素 + 时间 + 动效 + 文字」的粒度，就是照表编码 |
| 最终审美验收 | **建议由我或用户看静帧和成片** | 机器校验只能保证不遮挡、居中、时间对；保证不了「好看、不冗余」 |

### 最省时间的组合

由我一次性写好第 3–7 章的分镜表（约 30–45 分钟）。Codex 按交接文档逐章实现、渲染、校验，我或用户只看每章静帧拼图做验收。

如果用户希望完全交给 Codex：交接文档里也给了卡片模板和编排原则，Codex 可以独立完成，但建议每章交付后先看 4 张静帧拼图再放行。
