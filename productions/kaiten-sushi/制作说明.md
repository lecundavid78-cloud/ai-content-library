# 《回转寿司》第一版 · 制作说明

竖屏 H5 三消小游戏。纯前端，Canvas 2D 绘制，所有美术都是代码绘制的原创矢量图，没有用 Emoji、外部图片、CDN、后端、广告或付费。

## 1. 启动方式

- **直接打开**：双击 `index.html`（`file://` 也能运行，脚本都是普通 `<script>`，不是 ES Module）。
- **手机试玩**：把整个目录放到任意静态服务器上，例如在本目录运行 `python3 -m http.server 8000`，手机和电脑连同一个局域网后访问 `http://<电脑IP>:8000/`。玩完请关掉服务器。
- 桌面浏览器可以用鼠标试玩，建议在开发者工具里切到手机竖屏模式。
- 快捷键：`1/2/3` 直接进入对应关卡，`R` 重开，`Esc` 返回选关，`M` 静音。
- URL 参数：`?level=3` 直接进第 3 关；`?seed=123` 固定随机局面；`?debug=1` 打开开发者面板（显示 FPS、各位置寿司数量和不变量检查结果）。

## 2. 玩法（按第一版规则实现）

- 每关寿司总数固定，每种寿司数量都是 3 的倍数（加载时会校验，不符合直接报错）。
- 寿司从「入口」门帘出来，沿轨道走到「出口」后进入厨房队列，再从入口重新出来。循环时身份和数量都不变，顺序也保持先进先出。
- **点一下**传送带上的寿司：自动放入托盘，优先级是「已有同款的托盘 > 空托盘 > 暂存区」。
- **按住拖动**：拿起时寿司会弹起并跟手，可以放到指定托盘或暂存区的指定格子；松手在其他地方会飞回原位。
- 托盘锁定第一个放进去的种类。放入不同种类会被拒绝：托盘抖动、红框闪烁，并提示「这个托盘只放『××』」，寿司飞回原处。
- 同一托盘凑齐 3 个后自动消除：三个寿司依次跳起、向中间聚拢，然后爆出彩纸、米粒和星光，配冲击环、"好吃！/连击×2"飘字、音效和手机震动。之后托盘解锁。
- 暂存区 5 格，点击暂存区里的寿司会移到可以放的托盘。
- 寿司经过出口**不会**失败，只有时间耗尽才失败。全部消除即胜利，按剩余时间给 1–3 星，最佳成绩保存在本地。
- 完整流程：开始画面（选关）→ 开场提示 → 进行中（倒计时，最后 10 秒变红、闪烁并有滴答声）→ 胜利面板（下一关 / 再玩一次 / 返回选关）或失败面板（重新开始 / 返回选关）。左上角按钮随时重开本关。切到后台会自动暂停。
- **补货加速**（这是我自己加的规则，请确认是否保留）：传送带上寿司太稀疏、厨房里还有存货时，整条带子最多临时加速到约 1.9 倍，并在入口旁显示「加速上菜」。所有盘子同速移动，间距不变，不会重叠。加这条是为了避免玩家拿得快时长时间对着空传送带干等。不需要的话，在关卡里设 `refillBoost: 0` 即可关闭。

## 3. 目录结构

```
index.html                入口
src/core/ns.js            命名空间、可复现随机数
src/core/path.js          通用轨道路径：折线+圆角 / Catmull-Rom 曲线 / 多段拼接 → 弧长参数化
src/core/model.js         纯逻辑模型（传送带、厨房队列、托盘、暂存区、计时、胜负、不变量检查）
src/core/layout.js        竖屏自适应布局（安全区、各区域位置、触摸热区）
src/core/sushi-types.js   寿司种类目录（名称、瓷盘颜色、粒子颜色）
src/levels/level1~3.js    关卡配置
src/art/sushi-art.js      6 种寿司和瓷盘的原创绘制，并预渲染成精灵缓存
src/art/scene-art.js      纸纹背景、木桌、传送带、托盘、暂存区、HUD、门帘等
src/game/play.js          关卡场景：渲染、动画、触摸交互
src/game/menu.js          开始/选关画面
src/game/fx.js            粒子、飘字、提示气泡、缓动
src/game/audio.js         WebAudio 实时合成音效（没有音频文件）
src/main.js               画布适配、主循环、输入分发、调试接口
tests/sim.test.js         逻辑测试（Node）
tests/e2e.js              浏览器端到端测试 + 截图 + 录屏
tools/                    测试依赖（puppeteer-core），游戏本体不依赖它
out/screenshots/          真实游戏截图
out/preview.mp4           操作录屏
```

逻辑和渲染是分开的：`model.js` 不碰 DOM，所有规则都在模型里判断；渲染层只读取状态并做插值动画。所以动画怎么改都不会造成寿司复制或丢失。

## 4. 关卡配置怎么改

示例（`src/levels/level3.js`）：

```js
KS.registerLevel({
  id: 3, name: 'S 形蛇行', shape: 'S 形',
  track: {                      // 轨道（轨道空间 390×360，运行时等比映射到屏幕）
    type: 'polyline',           // 'polyline' 折线+圆角；'smooth' Catmull-Rom 曲线
    points: [[-80,76],[338,76],[338,180],[52,180],[52,284],[470,284]],
    radius: 52                  // 圆角半径；可以是数组，给每个拐点单独设置
  },
  beltWidth: 74, wall: 15,      // 带面宽度、围挡厚度
  spacing: 78,                  // 相邻瓷盘间距（沿轨道弧长）
  speed: 54,                    // 速度（轨道空间像素/秒）
  time: 105,                    // 时间限制（秒）
  sushi: { salmon: 9, tuna: 6, tamago: 6, maki: 6, ebi: 6, ikura: 3 },  // 必须是 3 的倍数
  refillBoost: 0.9,             // 可选：补货加速强度，0 = 关闭
  decor: []                     // 可选装饰：{kind:'menu'} 今日菜单（实时显示剩余数），{kind:'tip'} 文字提示
});
```

- **起点和终点放在画面外**（x<0 或 x>390），寿司就会从屏幕边缘出现和消失，门帘会自动画在边缘处。
- 做 180° 回转：两个拐点的距离等于 2×半径时，正好是半圆。
- **更复杂的轨道**：`track.segments: [{type:'smooth', points:[...]}, {type:'polyline', points:[...], radius}]` 会按顺序首尾相接，蛇形加折返的混合轨道可以直接配置（测试里有构建示例）。运动只依赖弧长 s，不依赖任何固定坐标。
- 新增关卡：复制一个 `levelN.js`，然后在 `index.html` 里加一行 `<script>`。
- 新增寿司种类：在 `sushi-types.js` 里登记，并在 `sushi-art.js` 的 `SUSHI_DRAW` 里写一个绘制函数。如果以后要换成美术出的 PNG，只需要把 `Art.sushiSprite()` 改成返回加载好的图片。

## 5. 测试结果

运行：`node tests/sim.test.js`（逻辑）、`node tests/e2e.js`（浏览器，需要先在 `tools/` 下 `npm i`）。

**逻辑测试：107 项全部通过**（完整输出在 `out/sim-report.txt`）

- 路径：三关采样连续，可见段长度正常；蛇形多段轨道也能构建。
- 布局：11 种屏幕尺寸（360×640 到 768×1024）下，HUD、传送带、三个托盘的热区、暂存区互不重叠，传送带不越过木桌。
- 循环：每关空转 10 分钟，每个寿司都循环过，总数不变，循环顺序不变。
- 模糊测试：每关用 40 个随机种子、约 48 万帧、数千次随机拿取/放置/取消/拿着不放（包括拿着时空盘过出口），**每一帧**都检查不变量，没有发现违反。检查内容：各位置数量之和等于总数、id 不重复、不丢失、传送带上不重叠、托盘类型一致、已消除数是 3 的倍数。
- 策略机器人（反应时间 0.6 / 1.0 / 1.4 / 2.0 秒，各 30 局）：三关全部 30/30 通关。用时中位数分别是：第 1 关 12–23 秒（限时 60 秒），第 2 关 19–48 秒（限时 85 秒），第 3 关 25–72 秒（限时 105 秒）。
- 超时才判负，出口循环不判负；拿着寿司时超时，寿司会被放回且数量守恒；托盘锁定和拒绝规则正确；凑齐 3 个后消除并解锁托盘。

**端到端测试：31 项全部通过**（完整输出在 `out/e2e-report.txt`），在无头 Chrome 里模拟手机竖屏，用真实触摸事件操作。

- 点击卡片进入关卡、点击自动放入、拖到已锁定托盘被拒绝并退回、拖到暂存区指定格、暂存区移到托盘，都正确。
- 三关都用触摸操作打通，已消除数等于总数，对局中每帧不变量都成立。
- 胜利后「下一关」、失败后「重新开始」、「返回选关」流程都正常。
- 4 种手机尺寸下没有界面重叠。
- 页面没有 JS 错误，运行期不变量检查失败 0 次。
- 性能：3 倍像素密度下，每帧逻辑+绘制的 JS 耗时平均 0.3ms；在 4 倍 CPU 降速下是 1.2ms（P95 1.7ms）。但降速时帧间隔约 33ms，瓶颈在无头 Chrome 的软件光栅化，不在 JS。真机通常有 GPU 加速，还没在真机上实测。

## 7. 已知问题

1. **没有参考视频**：拿取弹跳、飞行弧线、消除节奏（约 0.62 秒）、传送带速度都是我设的默认值，需要你试玩后调整。
2. 难度只用机器人校准过，真人手感需要试玩反馈。第 1 关偏宽松，是故意做成教学关。
3. 只在无头 Chrome 里测过，**没有在 iOS/Android 真机和小红书内置浏览器里实测**，包括安全区、手势冲突和音频解锁。
4. 音效是实时合成的占位音色，风格比较简单，建议换成正式音效。
5. 屏幕比 16:9 更矮时（例如平板或横屏），会整体缩小并在两侧留边，没有做横屏专门布局。
6. 字体用系统黑体，不是手写或圆体风格。
7. 玩家拿得很快时，传送带下游会出现空段（寿司只能从入口补充）。补货加速能缓解，但空段是这个规则本身的特点。

## 8. 下一步建议

1. 先在真机和小红书内置浏览器里试玩，按手感调整 `speed`、`time`、`spacing` 和动画时长。
2. 美术：换成正式手绘精灵图（接口已预留），加一款可爱的手写风字体子集，补齐正式音效和 BGM。
3. 玩法：放宽托盘规则（例如允许混放）、加道具（加时、洗牌、清空暂存区）、加连击奖励时间、做更多关卡（多段轨道、蛇形、交叉）。
4. 加关卡编辑预览页：在页面上拖动控制点，实时生成 `track` 配置。
5. 等确认后再处理小红书小工具的打包规范和接入，本轮没有发布。
