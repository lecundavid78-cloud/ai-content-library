## 1. 独立诊断：旧 18 秒为什么留不住人

**结论：建议重做视觉层。保留人像、声线、录屏和技术核验结论，推翻镜头语言、版式和渲染方式。**

### 1.1 时间码问题表（实测）

| 时间 | 实测数据 | 对观众意味着什么 |
|---|---|---|
| **0.00s 首帧** | 整屏数字人中景、无任何文字（字幕 0.12s 才出现）；平均亮度 75/255 | 首帧只有"一个人"，没有利益点也没有结果。抖音划走就在这一帧发生 |
| 0–2.5s | 字幕压在胸口 / 麦克风上；HeyGen 25fps 进 30fps 时间线 | 口播说"认准官方入口"，画面里没有入口。说的和看的对不上 |
| **2.5s 硬切** | 亮度 73 → 244（暖暗书房 → 纯白网页） | 手机上等于"闪白一下"，正是你说的生硬切换 |
| 2.5–5.0s | 录屏只占画面上部约 29%，下方大面积白底；帧差约 0（**源录屏本身在这段几乎不动**） | 页面小、空，看不清在哪个位置 |
| **5.0–10.0s** | **5 秒无人声**（RMS ≈ −44dB，讲话段 −16 至 −26dB）；6.0–7.0s、8.5–9.5s 帧差为 0；焦点框只是细线，8–9s 镜头滚到 winget 段时焦点框消失；**光标全程没有点击** | 全片最致命的一段："操作观看时间"里没有发生任何操作，也没有新信息 |
| 5–10s 底部小字 | "入口演示·尚未验证安装"在 360 宽下约 6px | 等于没写 |
| **10.0s 硬切** | 亮度 248 → 25（白页 → 深蓝黑页） | 第二次闪屏。三段三种底色，互不相关 |
| 10–15.4s | 10.0–11.5s 帧差全为 0；白字 + 一根箭头 | 静态 PPT |
| **15.5–18.0s** | **2.5 秒无人声 + 画面完全静止** | 凑时长的结尾；没有 CTA，也没有系列识别 |

**整体统计**
- **540 帧中有约 391 帧（≈13.0 秒）与前一帧零变化**。18 秒里只有约 5 秒在动，其中大部分还是开头 2.5 秒的数字人。
- 7.5 秒（42%）没有人声。BGM 约 −44dB 几乎听不见，所以这些时段是"死寂"，不是"留白"。
- 整体响度 −20.0 LUFS，比抖音常见的 −14 左右偏小。
- 出现三套色彩体系；数字人只露脸 2.5 秒，之后 IP 识别消失。

### 1.2 旧工程的问题
- `render.py` 用 Pillow 逐帧手绘，版式、时间点和图形逻辑都写死在代码里。结构固定为"数字人 → 两段录屏 → 一页关系图"，不能增减段落。
- Pillow 做不了高质量的模糊、蒙版、弹性动效和精细字距，这是画面"糙"的技术根源。
- 依赖 Windows 微软雅黑（未打包、商用授权不明），命令里有本机绝对路径。
- 字幕时间写的是"成片时间"。只要插入或删掉一段停顿，所有字幕都要手工重算。这种设计必然出错。

### 1.3 保留 / 推翻

| 保留 | 推翻 |
|---|---|
| 外观照（含胸前猫咪刺绣，可作 IP 小符号灵感） | 整屏数字人开场 |
| 悠悠君子 2.0 声线；第 1 期样片沿用现有 10.44 秒配音 | 白 / 深蓝 / 暖书房三套底色并存 |
| HeyGen 原片：**只在第 1 期**、以小角标形式使用（只对应这一段旧配音） | 5 秒无声"阅读"和 2.5 秒静止结尾 |
| 7.5 秒真实录屏（官方页面，内容真实） | 细线焦点框；整段英文段落放大 |
| 技术核验：桌面版 ≠ CLI；DeepSeek 不是 OpenAI 原生模型 | Pillow 逐帧绘制；Windows 字体；绝对路径；"成片时间"字幕 |

## 2. 前三秒：三个视觉差异明确的方向

三个方向共用的硬约束：
- **第 0 帧标题已完整可读**，不从空白淡入。
- **3 秒内进入真实录屏，不硬切**。
- 全片一块底色：取自外观照台灯光的「暖琥珀 + 深墨」，不用通用科技蓝。

### 方向 A｜「你问 · 我答」对话体系 ★ 推荐，已开始制作

> 核心隐喻：**观众向 AI 提的那个问题，我替你实测给出答案。** 片头是"问"（AI 指令框），正片是"答"（真实录屏 + 我的声音气泡）。人设"研究型 AI 教程"由此一以贯之。

| 时间 | 画面 |
|---|---|
| 0.00s | 深墨底 + 左上暖光晕。本期真实录屏**模糊、压暗、透视倾斜**地铺在背景里（暗示"后面有真东西"）。中上方两行超大标题已在，关键词带琥珀色荧光笔底。顶部是系列标签"AI 工具实测 · EP.01" |
| 0.1–1.4s | 下方品牌**指令框**（圆角输入条 + 猫咪符号 + 闪烁光标）逐字打出观众的痛点问题，如"Codex 去哪下载才是官方的？"，配轻微键盘音 |
| 1.4–1.8s | 发送键按下，指令框轻微下压回弹，发出"发送"音 |
| 1.8–2.7s | **答案登场**：标题收缩成顶部章节条，背景录屏去模糊、摆正，推进成统一的"窗口容器"。同一个镜头连续推进，不是切换 |
| 2.5s 起 | 左下角 IP 头像角标弹入，旁边出现"他说的话"字幕气泡；角标外圈声纹环随配音跳动 |

- **手机观感**：首帧有大字和一个所有人都认识的 AI 输入框；360 宽下标题约 38px 等效，指令框文字约 16px 等效。节奏是"打字 → 发送 → 推入"三拍，有网感但不吵。
- **复用成本：最低**。每期只改 4 个字段：标题行、高亮词、指令框问题、系列号。背景录屏自动取本期素材，动效代码不动。
- **IP 作用：强**。"指令框 + 猫咪符号"成为每期固定的开场记忆点；"头像 + 气泡字幕"成为全片固定的说话者识别。

### 方向 B｜「结果先行 · 真屏破框」

| 时间 | 画面 |
|---|---|
| 0.00s | 本期**最终结果画面**以 3D 倾斜大卡片占满屏，超大标题压在卡片上，部分笔画越出卡片边界 |
| 0–1.5s | 镜头沿卡片快速推近关键结果，同时出现"3 步"计数 |
| 1.5–3.0s | 卡片翻转，露出第 1 步的录屏 |

- **手机观感**：冲击力最强。
- **复用成本：中**。每期都需要一个真实、好看的结果画面。**第 1 期目前没有真实安装成功画面**，强行用就违反真实性要求。
- **定位**：做成母版中的可选段落 `result`（"结果特写卡"），等有真实结果的期数再启用。

### 方向 C｜「书房名片」

| 时间 | 画面 |
|---|---|
| 0.00s | 暖色书房虚化作背景，左侧圆形人像，右侧大字标题 |
| 0–1.5s | "本期你将学会"三点逐个弹出 |
| 1.5–3.0s | 人像缩成角标，书房"拉开"露出录屏 |

- **手机观感**：亲和，但首帧以人为中心，刷屏冲击力偏弱。
- **定位**：接近你不喜欢的"先摆一个人"，所以**不做片头**。只把它的暖光色调吸收进全片配色，并把"名片"形态用在结尾签名卡。

### 全片统一视觉语法（属于母版，不是单期设计）

1. **一块底，一个容器**：全片同一块深墨底 + 暖光晕。录屏始终在同一个圆角窗口容器里，靠"推 / 拉 / 平移 / 停靠"切换焦点，**从不换底色、从不清空舞台**。
2. **三级镜头**：每个录屏步骤都按"窗口全貌 → 推近操作位 → 结果特写停稳（≥1.2 秒）"走。放大倍数有上限（默认 ≤2.4 倍源像素），超过时校验器报警，避免糊图。
3. **标注语言**：琥珀荧光笔框 + 暗角聚光 + 一个"屏幕短字"标签（≤8 字）。**点击涟漪只在录屏中真实发生点击的时刻出现**；没点击就不画，不伪造操作。
4. **三线分工**：配音讲完整语境；气泡字幕逐句显示（每条最多 2 行 × 13 字，溢出报错）；屏幕短字只抓 3–8 字的重点；看录屏的那一秒，外部大字主动让位。
5. **转场只有一种**：同一容器的连续运镜 + 轻微运动模糊。
6. **声音四件套**：配音为主；原创合成 BGM 在人声出现时自动压低；固定提示音只有"打字 / 发送 / 焦点 / 转场"四种；成片统一响度到 −14 LUFS。
7. **结尾签名卡**（约 2.5 秒）：头像放大成名片，加下期预告、关注引导，以及**手机上不小于 12px 的真实性说明**。

## 3. 数字人策略：从"存在感"转向"识别度"

**默认方案（低成本稳定型）：头像角标 + 声纹环 + 气泡字幕**
- 角标直径约 168px（1080 宽画布），位于左下、字幕气泡左侧，构成"他在说话"的固定组合。位置避开平台右侧按钮列和底部文案区。
- 头像用外观照裁出的头肩像，**不动嘴，也绝不假装对口型**。"正在说话"由外圈**声纹环**表达，环的幅度由配音音量逐帧驱动。这和语音通话里"对方正在说话"是同一个人人熟悉的隐喻，观众会把它读作"这是他的声音"，而不是"假人在对口型"。
- 片头结尾弹入；讲解段常驻；结尾放大成签名卡。录屏焦点落到左下时，角标可按每期配置的区间自动避让。
- 每期成本 0，没有生成依赖。

**可选方案（精细口型型）**
- 母版支持把角标内容换成与本期配音口型一致的视频（`avatar.mode = "video"`）。**第 1 期样片就用旧 HeyGen 原片演示这一模式**，因为它正好对应旧配音，而且新时间线里配音保持连续、未变速，口型依旧对得上。
- 成本：上次观测 10.4 秒口播消耗 4 积分（外观 1 积分另计）。按时长线性推算，60 秒约 23 积分。**这只是推算，未核对 HeyGen 现行价目**。另有生成等待和失败重试的不确定性。
- 角标只有约 168px，口型瑕疵会被弱化，但每期付出 20+ 积分换一个小角标的口型，收益偏低。**建议只在开播、里程碑等特别期数使用。** 旧 10.456 秒原片不能用于任何新文案。

**真人配音**：真人声音的可信度和亲切感通常好于 TTS，也从根上消除"假人味"；代价是每期都要录音，状态也不稳定。母版对声音来源不设限，只要一个音频文件 + 逐字时间戳。**建议你用手机录一期同样文案对比**，不需要任何付费授权。

## 4. 技术方案与复用验证

### 4.1 选型：Remotion 4（React + TypeScript）+ FFmpeg

- **为什么不用 Pillow**：画面质量上限低，排版和时间写死在代码里。
- **为什么是 Remotion**：
  - 逐帧确定性渲染；无头 Chrome 出图，CSS 排版质量就是成片质量。
  - 所有动效都是"组件 + 参数"，每期内容只来自 JSON。
  - React/TS 是 Codex 最熟悉的栈。
  - 字体使用 npm 打包的开源思源黑体（Noto Sans SC，OFL），Windows 和 Linux 渲染一致。
- **FFmpeg 负责**：素材探测、配音包络（驱动声纹环）、原创 BGM 与提示音合成、最终响度标准化、手机预览与抽帧拼图。
- **风险与成本**：
  - **Remotion 许可**：个人及 3 人以内公司免费，超过需购买公司许可。**请你确认属于哪种。**
  - 渲染需要 Chrome。本机用系统 Chrome，Windows 上 Remotion 可自动下载 Headless Shell。
  - 本机 8 核渲染 15 秒成片约需数分钟。

### 4.2 工程结构（`master/`）

```
brand/brand.json             品牌层（长期固定）：配色、字体、动效时长、角标策略、提示音、安全区、放大上限
brand/assets/                品牌符号（SVG）；头像照片为私有素材，不进公开仓库
episodes/<期号>/episode.json  每期层：标题、指令框问题、段落数组、录屏片段与运镜、配音片段、字幕、CTA
episodes/<期号>/media/        本期素材（录屏、配音、可选口型视频）
src/                         视觉组件：Opener / ScreenStage / Explain / Outro / CaptionBubble / AvatarBadge / ChapterBar
src/engine/                  纯函数时间引擎：配音时间 → 成片时间映射、运镜关键帧、布局（校验器与渲染共用同一份代码）
scripts/                     validate / render / audio（BGM、提示音、包络）/ preview（手机预览、拼图、安全区叠层）
docs/                        Codex 每期工作单、变量清单、素材来源与许可、失败处理
```

**关键设计**
- **段落数组**：`opener → screen → explain → screen → … → outro`，可任意排序和增减。
- **时间锚点**：字幕和运镜可以写"配音时间"（`{"v": 4.08}`），引擎自动换算成成片时间。在配音里插入或删除停顿，不用重算任何字幕。这是对旧工程最大的结构修正。
- **显示稿 / 口播稿分离**：`script.display` 用于字幕，`script.tts` 用于送 TTS（例如英文专名的读音引导）。

### 4.3 复用验证（不是"JSON 看起来能改"）

1. 用同一个 `src/` 和 `brand/` 渲染两期**题目、录屏、文案、配音状态都不同**的样片。
2. 渲染报告写入 `src/` 与 `brand/` 的 SHA-256。**两期哈希相同**，证明换期时没改核心代码。
3. 两期抽帧并排对比，确认标题、字幕、焦点、过渡都来自各自的 episode.json，没有残留上期内容。
4. 校验器用故意写错的配置自测：超长标题、超长字幕、缺文件、放大过度、标注压到头像等，都必须明确报错。

## 5. LINUXDO《产品宣传片教程》方法论迁移

### 5.1 吸收了什么、用在哪里

| 原文逻辑 | 在本项目中的落地 |
|---|---|
| 先定"给谁看、记住哪一件事" | `episode.json` 必填 `audience` 和 `oneThing`（一句话），并写入工作单的第一步。EP01 的 oneThing：**"Codex 要从 OpenAI 官方文档页下载"** |
| 前几秒抛与观众切身相关的痛点，下一秒亮出真实界面 | 方向 A：指令框打出观众的原话痛点，"发送"后 1 秒内真实录屏推入。砍掉寒暄、目录和整屏数字人 |
| 三级镜头：完整设备 → 页面内真实点击 → 结果特写停稳 | 录屏组件的 `shots` 固定为 `full → focus → hold` 语法；hold 默认 ≥1.2 秒，校验器检查 |
| 不要每讲一句就清空画面，同一主体留在场上接力 | 窗口容器是贯穿全片的**持久图层**：片头作为模糊背景出现 → 正片成为主体 → 讲解段停靠到上方作为"证据"继续在场 → 结尾才退场 |
| 旁白、屏幕大字、真实界面三线分工 | 气泡字幕 / 屏幕短字（≤8 字）/ 录屏，各自独立配置；录屏特写时外部大字让位 |
| 显示稿与口播稿分开 | `script.display` / `script.tts` 两个字段 |
| 先测准真实音长再排画面；觉得拖就删词，不要倍速 | 时间锚点直接绑定配音时间戳；配音只允许 1.0 倍速，校验器拒绝变速 |
| 先做 15–20 秒小样，锁住满意部分，每次只改一处 | 本轮交付 15 秒级小样；工作单要求每次改动"锁定 + 只改一处 + 另存版本号" |
| 交接记录 | `docs/交接记录.md`：已锁定项、素材位置、下一轮只改什么 |
| 父子容器同时动会"抽动" | 引擎规定一个时刻只有一层负责运镜（窗口容器或内容，二选一） |
| 演示数据要干净 | 工作单写明：录屏前清空无关标签页、通知、真实密钥，使用演示账号 |

### 5.2 不适用或需要改造的部分

- **Seedance 实景底片 + 黑屏合成**：我们是教学片，主体是电脑录屏，不需要生活实景。合成反而增加成本和"假感"。**不采用**，也不调用任何生成服务。
- **MiniMax 换声**：用户已锁定豆包悠悠君子 2.0，不另试声线；如需对比，优先建议真人配音。
- **90 秒首发片的五步疑问表**：教学片的疑问顺序本身就是操作步骤，简化为"痛点 → 每步（全貌 / 操作 / 结果）→ 下一期"。
- **品牌形象片（物件轮廓快剪）**：现阶段没有确定 Logo，暂不做。以后有正式 Logo 时，可以借用"猫咪轮廓"的思路做账号形象短片。
- **"一分钟讲完全部功能"的冲动**：原文反对功能报菜名。迁移到本项目就是**一期只教一件事**，所以第一期 60 秒能否同时讲清"安装 + 接入 DeepSeek"值得重新考虑，建议拆成两期（见第 6 节）。
