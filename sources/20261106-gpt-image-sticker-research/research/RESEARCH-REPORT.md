## 0. 研究结论（先看这段）

### 0.1 一句话

**能做成可演示、可交付的表情文件链路已有充分公开证据；「上架后必赚 / Image 2.6 一夜千元」没有可靠证据。** 首期视频应拍「母图 → ChatGPT 原生 GIF → 本地压到微信规格并自检」，变现只并列讲机制与证据强弱。

### 0.2 推荐拍摄路线（本轮首选）

**ChatGPT 网页原生 GIF + 本地微信规格检查（必要时再让 ChatGPT 二次压缩）**

| 项 | 内容 |
|----|------|
| **为什么首选** | 歸藏/路飞/Gorden 有可下载动图成品；杰哥长文把投稿规格与压缩说清楚；初学者不需 API Key、不需装 Agent |
| **不首推** | Ray `ray-sticker-shop` API 批处理（高阶备选）；整组九宫格切图当微信动态专辑；未授权 IP/名人定制 |
| **演示角色** | 必须用**自有版权**角色或宠物照；歸藏完整提示词**仅授权作方法模板**，视频勿示范大肥鱼原 IP |
| **变现口径** | 「可做成投稿/客户交付文件」；赞赏与闲鱼报价一律标「作者自述」；明确**不算躺赚** |

### 0.3 六条最重要结论（供制片核对）

1. **OpenAI 于 2026-11-04 正式发布 Images 2.6**；ChatGPT 侧称 ChatGPT Images 2.6；API 为 `gpt-image-2.6-sunburst`（偏细节）与 `gpt-image-2.6-flare`（偏速度），标准价文本输入 **$5**、图像输入 **$8**、图像输出 **$30** / 百万 token——**无官方固定「每张 $x」**；GIF 帧数参数文档为 **2–16**。勿笼统说「国内人人可用」。
2. **首期演示路线**：同一张母图 + 固定提示词模板逐张出原生 GIF → 压到 **240×240、≤500KB、可循环** →（可选）补封面/图标/横幅。Ray 的「每表情一张 4×4 精灵图 + Pillow 切帧」是高阶自动化，**首次视频不首选 API**。
3. **角色一致性**靠「同一母图 + 提示词锁死发型/配色/道具」；拉高到约 30 帧会漂、清晰度下降（歸藏回复）。中文配字可写进提示词（2–8 字）或后期自加。
4. **透明底与微信投稿**：多帖承认痛点；官方封面/图标要透明；表情图多为白底再抠或模型 alpha。本轮材料**未点名 rembg 已用**；Ray 代码依赖模型 `background=transparent` + Pillow，**无 rembg**。聊天浅色/深色底缩图清晰度：**缺系统实拍证据**。
5. **变现**：个人/宠物定制（谁付钱清楚，价格多为自述）；品牌单缺公开成交；微信赞赏机制官方清晰但**无官方均值收入**。黄啊码截图单套赞赏 ¥1369、账号累计 ¥2534，作品「最后更新」为 **2025-09**，评论质疑与 GPT 无关，作者称「分享思路」「以前用即梦」。blune66 反证多套赞赏为 `-`。
6. **媒体格式核量**：X 上多数「GIF」附件下载为 **MP4（tweet_video）**，**不是**可直接上传微信的 GIF；路飞等附件偏短，仅作效果预览。`video-frames/` 是对 Ray 演示视频的**真实抽帧**，不是整帖伪造截图。

### 0.4 几种制作路线各自怎么做

| 路线 | 怎么做 | 代表 | 首期适用 |
|------|--------|------|----------|
| A. 参考母图 → 逐张原生 GIF | 上传同一角色图 + 模板，只改主题 | 歸藏、路飞、Gorden | **首选演示** |
| B. 极简口语一句 | 「做一只猫骑扫把」几乎不写提示词 | web30708 | 对照，不可控 |
| C. 整组多宫格静图再切 | 一图 3×3/九表情再切 | SUOHA | 梗图/预览，≠微信动态专辑 |
| D. 原生 GIF + 规格化投稿 | 再压 240、补三件套、填含义词 | 杰哥、麻酱 | **与 A 组合讲交付** |
| E. 每表情一张 4×4 帧精灵图 | API edits → Pillow 切 16 帧 GIF | Ray skill | **高阶备选，不首选** |
| F. 四宫格静帧拼 GIF | 无原生 GIF 时的 fallback | 杰哥文中备选 | 兼容旧入口 |

【角色保持一致】
保留参考图中的：【列出发型/配色/标志道具/服装】。
保持原图的大头小身体 Q 版比例、圆脸和可爱画风，人物外观在所有帧中保持一致。

【自动设计动作】
理解我想表达的情绪或梗，将它设计成一个简单、有趣、一眼能看懂的短动作。
突出一个核心笑点，用夸张表情、动作反差和轻微的压缩回弹增加喜感。服饰与标志部件自然跟随动作。
根据主题添加必要的少量道具，保持画面简洁。
主动设计首尾衔接，让动画能够自然循环播放。

【自动配字】
根据主题提炼一句简短、有网感的中文配字，优先控制在 2～8 个字。
如果主题中用引号指定了台词，直接使用该台词。
字幕放在顶部，使用粗圆体、深色字、白色描边；文字、字形和位置全程稳定，角色与道具不遮挡字幕。

【画面与输出】
正方形画面，纯白背景，固定镜头，主体居中并保留足够边距。
动画约 2～3 秒，无限循环，动作清晰，适合聊天时作为表情包发送。
最终交付实际会播放的多帧 GIF 文件，并提供下载。

表情包主题：【在这里填一句话，描述你想表达的梗、情绪或动作】

## 3. 制作方法比较（实用性）

### 3.1 对照

| 维度 | 整组多宫格再切 | 逐张原生 GIF | 每表情 4×4 精灵图 | 参考扩展 | 静态 vs 动态 |
|------|----------------|--------------|-------------------|----------|--------------|
| 一致性 | 同图内一致，跨套弱 | 靠母图+锁特征 | 靠同一 character.png | 同左 | 本波主叙事=动态 |
| 中文配字 | 可写进格内 | 提示词 2–8 字或后期加 | caption 嵌入每格 | — | — |
| 透明底/边缘 | 静图抠图 | 白底为主；透明后处理 | 模型 alpha；贴边需修（Ray 视频有修正） | — | 封面/图标必须透明 |
| 工具 | 手工/脚本切图 | ChatGPT；X 下载多为 MP4 | Pillow；无 rembg | ChatGPT 参考图 | 微信动态=GIF |
| 耗时/重试 | 出图快，切图另算 | 杰哥「不到一分钟」/张（自述） | 文档「几分钟」整套（未证实） | — | — |
| 聊天缩图 | **缺实拍证据** | 同左 | Ray 有预览页，**非微信内实拍** | — | — |

### 3.2 媒体格式核量（拍摄必懂）

| 现象 | 含义 |
|------|------|
| `media/selected/**/*.mp4` 且来自 tweet_video | X 把动图转成 **MP4 预览**，**不能**当微信上传 GIF |
