## 3. 主题过滤规则

**纳入**：标题/正文/章节明确 Codex、腾讯 WorkBuddy，或与普通人使用两工具强相关（选型、安装、积分、办公 vs 编程、Agent 协作）。

**排除或降权**：

- 纯 AI PPT / AI 赚钱 / 副业引流，仅因高赞 → **不入选**（例：索引中「真正无痛开启自媒体副业…#WorkBuddy」未选）
- ChatGPT Work ≠ WorkBuddy（大白画 AI）→ 不入 16 条（作身份澄清背景，非候选）
- 正文未提 Codex/WB（尘尘个人 Agent 横评）→ 不入选
- CodeBuddy IDE 混称：不把 CodeBuddy 当 WorkBuddy；B06 因混称**旗标研究价值**保留并标明

## 4. A 组排名逻辑（传播候选）

因未完整观看，**不计算** 35/25/20/10/10 加权总分。

可核验排序信号（综合，非单一公式）：

1. 近窗优先的互动强度（赞/藏/转；评在短视频上单独加权）
2. 相对账号规模（强调中小/极小账号相对表现）
3. 赞藏结构差异（藏≥赞、评赞比异常等可研究形态）
4. 已有评论是否出现本期核心问题（DeepSeek/WB、GitHub、翻墙、普通人够用）
5. 形式多样性（喂饭教程 / 痛点短片 / 结果案例 / Skill 清单 / 长教程 / 锐评榜 / 提问框 / 历史合集）

刻意**未做**：只取绝对最高赞；用 5 月前 几十万赞 Codex 教程（里昂/秋芝/谢慢慢等 L1）挤掉近窗已核验样本。

开头吸引力、剪辑节奏、表达质量 → 统一 **待观看评估**。

## 5. B 组排名逻辑（内容潜力）

依据标题 + 章节要点/文稿 + 评论线索判断「是否值得深挖」，不是打准确性分数。

优先信号：

- 有任务/评测设计（财叔 PPT×积分）
- 有可陈述框架（徐老师交付物二分；匪叔课纲；小博定位）
- 有痛点证据（老樊评论；大白话分层+混称）
- 有方法句（阿谦：小任务试用看返工与消耗）
- 小博主 + 传播一般但结构清楚
- 主题缺口补位（Keith：GrokBot×Codex）——降权并标 L1

「超全/保姆级」只当标题现象，不当质量分。

## 7. 缺失数据与处理

| 缺失 | 处理 |
|------|------|
| 播放量全无 | 不算转赞率/完播率；不打零，标无法获取 |
| 多数无收藏/评论（L1） | A 组几乎只用已详情核验条 |
| author_url 全空 | 粉丝取深挖页快照 |
| 绝对时间仅部分 | 相对时间条目单独注明 |
| 章节 ASR 噪声 | 标注谨慎引用 |
| 评论未翻页 | 只引用已采首屏 |

缺少数据 **不自动打零分**；改为降低证据等级或改标「待验证」。
